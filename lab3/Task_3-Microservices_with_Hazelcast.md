**Lab 3 \- Мікросервиси з використанням Hazelcast Distributed Map**  
**(10 балів)**

Завдання базується на першому завданні і є його подальшим розвитком.

У першому завданні всі данні про транзакції зберігались у памʼяті, що призвело б до їх втрати у випадку перезапуски сервісів.  
Також зберігання всіх транзакцій на ***logging-service*** призвело б до його переванатаження та закінчення оперативної памʼяті.  
Тому, у даній ітерації:

- для балансування навантаження, ***logging-service*** необіхдіно буде запустити в декількох екземплярах,   
- у якості сховища для логів використати In-Memory Distributed Map на базі **Hazelcast**,   
- у якості сховища  для збереження значень на рахунках одну з дискових DB 

До ***logging-service*** необхідно додати:

- у якості сховища повідомлень **Hazelcast Distributed Map**   
- можливість запускати одночасно декілька копій ***logging-service***  
- ***facade-service*** випадковим чином обирає до якої копії ***logging-service*** звертатись для запису та читання повідомлень


До ***counter-service*** необхідно додати:

- PostgreSQL, або MySQL, або MongoDB (варіанти використання інших DB треба узгодити) у якості сховища повідомлень

Приклад реалізації можна подивитись на відео: [https\://youtu.be/D4mkt6t1Nzk](https://youtu.be/D4mkt6t1Nzk)  

**Функціональність системи**

Клієнт взаємодіє з ***facade-service*** через HTTP POST та GET запити. У якості клієнта може бути *curl*, *Postman*, браузер у Dev mode та інше

- ***logging-service*** використовуючи клієнт Hazelcast підключається до своєї ноди кластеру Hazelcast (кластер Hazelcast складається з 3-х нод)  
- ***logging-service*** використовує **Hazelcast Distributed Map** для збереження повідомлень замість локальної хеш-таблиці  
- ***counter-service*** використовує **DB** для збереження повідомлень замість локальної хеш-таблиці  
- ***facade-service,*** з яким взаємодіє клієнт, випадковим чином обирає екземпляр ***logging-service*** під час відправки POST/GET (GRPC) запитів  
- якщо обраний екземпляр ***logging-service*** недоступний, то обирається наступний і т.д.

**Завдання**

- Запустити три екземпляра ***logging-service*** (кожен з екземплярів запускається у власному Docker-контейнері),   
- Відповідно має запуститись також кластер Hazelcast з трьох серверів  
- Через HTTP POST виконати 10 транзакцій *msg1-msg10* через ***facade-service*** та перевірити коректність зміни значення балансу на рахунку у counter-service, та збереження самих транзакцій у *logging-service*  
- Показати які повідомлення отримав кожен з екземплярів ***logging-service*** (це має бути видно у логах сервісу)  
- Через HTTP GET з ***facade-service*** прочитати транзакції  
- Перевірка відмовостійкості:  
  - Вимкнути один/два екземпляри ***logging-service*** та перевірити чи зможемо записати та прочитати транзакції   
  - Вимкнути один/два ноди Hazelcast та перевірити чи зможемо записати та прочитати транзакції
